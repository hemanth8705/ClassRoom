The Empty Canvas: From Noise to Tokens

Before a text-to-image model can paint anything, it needs a canvas it can read. This page shows how that canvas is made and how it is turned into the same "list of rows" format as your text. Everything here is interactive.

Pick the picture you want

Assumptions used here (illustrative, taken from the LTX family from memory, not verified against your checkpoint): each cell covers a 32 × 32 block of pixels, every 8 video frames become 1 latent frame, C = 128 and W = 4096. The ideas are the same for any model; only the numbers change.

STEP A

Make the starting canvas

A1. The picture is first shrunk into a grid of "cells"

Working on every pixel would be slow, so the model works on a much smaller grid. Each 32 × 32 block of pixels will be represented by one cell. A helper called the VAE does this shrinking and, at the very end, the expanding back.

A2. Each cell holds a list of numbers, not a colour

A cell is not "red" or "blue". It holds C numbers (its channels). Think of C as how many measurements the VAE uses to describe one block of the picture: shapes, textures, brightness, and things we don't have words for. At the start we haven't painted anything, so every number is random noise.

Click any cell. (For display, three of its numbers are used as red, green, blue. The other C−3 are hidden.)

A3. The 5 dimensions, in plain words

The canvas has the shape [batch, C, frames, height, width]. Humans can picture 3 directions, so split it like this:

  • height × width is the flat sheet of paper (here the grid above).
  • frames is how many such sheets are stacked, like pages in a flip book. An image has 1 sheet.
  • C is how many numbers are written inside each cell of each sheet. It is not a 4th direction in space, it is the depth of the data stored in each cell.
  • batch is how many separate canvases we make at once. We make 1.
STEP B

Cut the canvas into tokens

The model doesn't read a 2D sheet. It reads a list of rows, the same format as the text grid from the previous article. So we take every cell of every sheet and write it as one row. Each cell becomes one image token.

Hover a cell to see its position in the list. Token number = row × width + column (for the first frame).

The count. Number of tokens N = frames × height × width. For the picture you picked this is shown in the shape box at the top. Our default is 1 × 16 × 24 = 384. (Not 348.)

B3. What are C and W? They are different things

C (channels) is decided by the VAE. It is how many numbers describe one cell of the shrunken picture. It has nothing to do with how many inputs the model accepts.

W (model width) is decided by the main model. It is the length of the row the model uses internally for every token, like the width of the page the model does all its thinking on. It is usually much larger than C because the model needs more room to think about a cell than the VAE needs to store it.

The two are different sizes, so one simple layer sits between them. It is a single table of learned numbers of size C × W. Each token's row (length C) is multiplied by this table and comes out as a longer row (length W). Same tokens, same order, just re-written on the model's wider page:

That's the end of Step B. The image is now in the same form as the text: a list of rows. In the next part we'll see how the model uses both lists together.

DEEP DIVE

C and W, explained with small numbers

1. What C means: the cat/dog scorecard, but for pieces of a picture

Remember the scorecard for words (animal, hair, queen, king, furniture)? A cell of the picture gets a scorecard too. Here is a toy one with C = 5 features. Each row is one cell, the way "cat" was one row before.

cell of the picturebrightnessrednessbluenessedginesssandy texture
cell in the sky0.900.300.800.050.00
cell on the sand0.700.600.200.100.90
cell on the car0.400.900.100.800.00

Read it the same way as before: a sky cell is bright and blue with no edges, a sand cell is sandy, a car cell is red with strong edges. C is the number of columns, which here is 5. A real VAE uses something like 128 columns.

Honest note: real channels have no names like "redness". The VAE learns its own 128 columns while being trained to shrink and rebuild millions of pictures. No single column means one thing you could point to. Together they hold enough information to rebuild the 32 × 32 block of pixels the cell stands for.

At the start of generation these numbers are random noise. By the end of the denoising steps they hold real values like the ones in the table above, and the VAE decoder turns them back into pixels.

2. What W means: a plain neural-network picture

You may know the simplest model there is: linear regression. It takes some inputs (x1, x2, x3), multiplies each by a learned weight, adds them up, and gives one output:

y = w1*x1 + w2*x2 + w3*x3

Now imagine doing that several times side by side, each with its own set of weights, all reading the same inputs. You get several outputs instead of one. That is exactly what the "linear layer" between C and W is. Here is a tiny version with C = 3 inputs and W = 4 outputs:

Every line carries one learned weight. 3 inputs × 4 outputs = 12 weights, so a table of 3 × 4.

3. The arithmetic, with the sky cell

The sky cell from the table, using only its first three features: x = [0.9, 0.3, 0.8]. Suppose training has produced this 3 × 4 weight table:

out 1out 2out 3out 4
from brightness1.0-0.50.20.0
from redness0.51.0-0.30.4
from blueness0.00.51.0-1.0
out 1 = 0.9*1.0 + 0.3*0.5 + 0.8*0.0 = 0.90 + 0.15 + 0.00 = 1.05 out 2 = 0.9*-0.5 + 0.3*1.0 + 0.8*0.5 = -0.45 + 0.30 + 0.40 = 0.25 out 3 = 0.9*0.2 + 0.3*-0.3 + 0.8*1.0 = 0.18 - 0.09 + 0.80 = 0.89 out 4 = 0.9*0.0 + 0.3*0.4 + 0.8*-1.0 = 0.00 + 0.12 - 0.80 = -0.68

3 numbers went in and 4 came out. Each output is a different blend of the same three inputs. The weights are not picked by hand; they are learned during training, just like the weights in linear regression.

4. So what is W, and why is it bigger than C?

  • C is how many numbers the VAE needs to store one cell. It only has to be enough to rebuild the pixels.
  • W is how many numbers the main model uses to hold one token while it thinks. That includes "what is this cell", "what is next to it", and "which words from the prompt matter to it". That needs far more room than storing the cell.
  • In the toy example above, C = 3 and W = 4. In the real model, C = 128 and W = 4096, so 128 inputs fan out to 4096 outputs, and the weight table is 128 × 4096 = 524,288 numbers.
  • The only job of this layer is to move each token from the VAE's row length (C) to the model's row length (W). The number of tokens and their order do not change.

5. Where each one lives

The VAE speaks in C. The main model speaks in W. The linear layer is the translator between them.

STEP B, IN DETAIL

How the image tokens go from C to W

1. Why bother? Room to work

Storing a cell needs only a few numbers: just enough to rebuild its pixels. Doing the model's work on that cell needs more room. While the model thinks, each token has to hold things like "what am I", "what is around me" and "which words of the prompt matter to me". A bigger row gives it space for all of that.

Think of C as a short note and W as a full page. You can copy a note onto a page, but the page is where you do the working.

2. One table, applied to every token

All N tokens sit in a table of N rows and C columns. We multiply the whole table by one learned table of C rows and W columns. The result is a table of N rows and W columns.

The highlighted row is one token before and after. Row 95 of the left table (a row of C numbers) becomes row 95 of the right table (a row of W numbers). Nothing is reordered and no token is added or removed.

before : [N, C] e.g. [384, 128] 384 tokens, each a row of 128 numbers table : [C, W] e.g. [128, 4096] the same 524,288 learned numbers for all tokens after : [N, W] e.g. [384, 4096] 384 tokens, each a row of 4096 numbers

3. Common misunderstandings

"W is the neural network." Not quite. W is the width of the row the network works on. The network is the many layers and all their weights. This C → W table is only the first layer.

"The new space holds new information." Not yet. Right after this layer, the W numbers are just blends of the C numbers. Think of re-writing a 128-word note on a 4096-line page: the page is bigger but the note hasn't grown. The later layers are what fill the extra room, by mixing in information from neighbouring cells and from the prompt.

"Each cell has its own table." No. One table, shared by every token. That is why the model works for any picture size: add more cells and you just add more rows.

4. What does bigger W cost?

  • More room to think, so usually better results.
  • More memory and compute. The model's weight tables grow roughly with W × W, so doubling W makes them about four times bigger.

Model designers pick W as a balance between quality and cost, which is one reason models come in sizes like 12B or 22B.

5. Where does the prompt land?

The text grid from the first article has its own row length, D, which comes from the text model. It is also converted to the model's working width, W, using its own learned tables. Once both the image tokens and the text tokens are rows of the same length W, the model can compare them. That comparison is the subject of the next part.

image tokens : [N, C] -> [N, W] text tokens : [T, D] -> [T, W] <- both now at the same working width next step : compare each image token with each text token

Numbers (128, 4096, 524,288) are illustrative, as before.
